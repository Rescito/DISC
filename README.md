# DISC Reflection — саморефлексивный опросник

Компактное веб-приложение на русском языке: 36 коротких сценариев × 4 ответа, ранжирование всех четырёх реакций от 1 (характернее всего) до 4 (менее характерно), три раздельные линейные графика и секундомер. Вопросы относятся к повседневным контекстам, а не только к работе. Поддерживает смартфон, печать и сохранение отчёта в PDF.

## Важное ограничение методики

Это **не сертифицированная система DISC и не психометрически валидированный тест**. Авторский сценарный набор — только инструмент самонаблюдения; результаты не предназначены для кадровых решений, диагностики или точных личностных заключений. Принудительное ранжирование даёт относительный ipsative-профиль: высокие доли означают приоритет внутри конкретных ответов, а не абсолютный балл или сравнение с нормативной выборкой. Представление «стресс-профиля» — исследовательская гипотеза по самоописанным ответам, а не измерение реакции в реальном стрессе. Для заявлений об «очень точных» результатах нужны разработка и проверка методики: экспертная проверка содержательной валидности, когнитивные интервью, пилотирование, надёжность, валидность на релевантной выборке, нормы и аудит смещений.

## GitHub Pages: опубликовать интерфейс

1. Создайте репозиторий, например `disc-reflection`.
2. Добавьте `index.html` и `questions.json` в корень репозитория.
3. Включите **Settings → Pages → Deploy from a branch**, выберите `main` и `/ (root)`.
4. GitHub Pages отдаёт статические файлы по публичной ссылке. Это не серверная платформа; email напрямую и безопасно из браузера отправлять нельзя.
5. В `index.html` замените `YOUR-WORKER.workers.dev` на URL вашего Cloudflare Worker. Если endpoint не настроен, локальная часть работает, профиль строится, таймер работает, доступна печать в PDF, а страница честно сообщает, что email не отправлен.

## Настроить email (Cloudflare Worker + Resend)

1. Создайте аккаунт Resend, подтвердите домен отправителя и получите API key. Отправитель должен быть подтверждён в Resend; адрес получателя `s.k.g@mail.ru` сам по себе не подтверждает права на отправку от него.
2. Создайте Cloudflare Worker из файла `worker.js`.
3. В настройках Worker добавьте secrets/variables: `RESEND_API_KEY` (secret), `FROM_EMAIL` (например, `DISC Reports <reports@ваш-домен.ru>`), `ALLOWED_ORIGIN` (точный origin GitHub Pages, например `https://username.github.io`; без завершающего `/`). Для тестирования с другим доменом обновите ALLOWED_ORIGIN.
4. Разверните Worker, скопируйте URL и вставьте его в `API_URL` внутри `index.html`.
5. Проверьте поток тестовой формой: письмо приходит на `s.k.g@mail.ru` и на введённую почту. Проверяйте папки «Спам» и лимиты провайдера.

### Безопасность и приватность

- API key хранится только как Worker secret, никогда не помещайте его в HTML, GitHub или браузерный JavaScript.
- Worker отправляет только итоговые агрегированные баллы, имя, email, выбранный контекст, заметку и длительность; ответы по сценариям клиент не отправляет.
- Опросник просит согласие до старта. Перед реальным использованием добавьте свою политику конфиденциальности, сроки удаления писем, контакт администратора и правовое основание обработки персональных данных согласно применимому законодательству. Email-провайдер хранит письмо и метаданные по своим правилам; формулировка «не сохраняются» относится лишь к коду статического приложения.
- Добавьте rate limiting/защиту от злоупотреблений перед публичным массовым запуском. Worker сейчас проверяет origin и поля, но Origin не является аутентификацией и CORS не предотвращает все виды автоматизированных запросов.
- Не собирайте специальную категорию персональных данных. Не используйте для отбора кандидатов, оценки здоровья или иных решений с высокими последствиями.

## Скоринг

В каждом из трёх блоков (12 ситуаций) все четыре ответа ранжируются. Ответ с местом 1 получает 4 балла, 2 — 3, 3 — 2, 4 — 1. Сумма по шкале преобразуется в долю от общего числа баллов блока; графики показывают четыре относительные доли, суммирующиеся до 100%. Порядок вопросов и ответов случайный; метки D/I/S/C респонденту до отчёта не показываются. Связь вариантов с условными шкалами и сами сценарии в исходном коде можно обнаружить, поэтому это не защита от мотивированного угадывания.

## Структура

- `index.html` — интерфейс, мобильная адаптация, таймер, перемешивание, визуализация.
- `questions.json` — сценарии/ответы и ключи трёх контекстных блоков.
- `worker.js` — необязательная отправка двух писем через Resend.
